4. Second live attempt: `bravo_health_gate.sh` recovered Bravo successfully FOUR times in its own log (`recover result='OK CUL'` x4, including auto-handling a real ClickOnce prompt correctly) — yet still reported the overall gate as `FAIL no-dashboard`. Fixed with a new `latest_store_files_by_mtime()` locator (ignores filename convention entirely, just picks the most recently modified match) and switched Job C to use it.

**Bottom line: none of Job E's failures today were "Bravo is fundamentally broken."** Two were real (small) bugs in this new code, one was a stuck dialog needing one human click, and one is a pre-existing bug in the hardened `bravo_health_gate.sh` script that's outside this project's scope to fix but worth reporting.

**Two real bugs found and fixed via dry-run, before anything reached Slack:**
1. **LEX's June 2026 data was mislabeled `2026-07`** by the handler (bucket names literally say "JUNE 2026," but the Month field the handler tagged said July — likely a query-context artifact, not a bucket-name parse). Uncorrected, this made the render show LEX as "0 dwt, may still be open" — false; LEX had real data (65.07 dwt). Corrected directly in the history CSV (one row, `2026-07` → `2026-06`) since the evidence (bucket name text) was unambiguous. Note: ROA and WAY also have some buckets whose *names* reference an adjacent month lumped under one Month tag, but without a similarly stark reporting error (no false "may be open" flag), so those were left as recorded — only LEX's case produced a materially wrong render.
2. **YTD math was nonsensical the first render** (`-76%`): comparing 2026's single backfilled month against a full Jan–June 2025 cumulative (apples-to-oranges, since Jan–May 2026 was never backfilled — that data may not even exist as closed buckets yet). Fixed: YTD now sums only the current-year months actually present in history against their exact prior-year equivalents — naturally becomes a true multi-month YTD as `job_gold_trend` accumulates real months going forward, rather than a misleading number today.
- **Known, disclosed (not fixed) data-completeness gap:** "Best month T12M" is mathematically correct given available data, but the trailing-12-month window for a mid-2026 report month includes Jan–May 2026, which have no history rows (they sum to 0, not "genuinely zero") — so a real high month in that gap could currently be missed. Self-corrects as the recurring job fills in each month going forward.
