# Scoreboard — week of Aug 31 – Sep 6, 2026

**Read the note before the numbers.**

This run covers Aug 31 – Sep 6, which is the *same week* the manual baseline was built from
(`FINDINGS_v2_2026-08-31_week.md`). The scheduled task's window rule — previous Monday through
Sunday — lands on the baseline week because the program was stood up mid-week. So the column
headed "this week" and the column headed "baseline" describe the same 266 calls.

**Nothing below is week-over-week movement.** It is a re-measurement of one week with the full
rubric applied call by call, where the baseline was estimated from a first pass. Where the two
disagree, the difference is measurement, not performance. The first genuine trend line is next
Monday's run over Sep 7–13.

### Why conduct went from ~20 to 57

Not because the week got worse — it is the same week. The baseline counted the incidents that
stood out on a first read. This pass tagged every call against the rubric, and the systematic
verification failure — 69 disclosures, none verified — turned a large number of ordinary,
well-mannered calls into MEDIUM items. Strip the verification category out and the "things a
person did wrong" count is roughly 20, which is where the baseline was.

That is the real finding: **the biggest conduct problem in this business is not rude employees,
it is a missing procedure.** Most of these 57 calls are polite, helpful people doing exactly what
nobody has told them not to do.

disclosures. Audio is pulled for every one.

Harrisonburg where staff answer "Waynesboro," and two greetings that transcribe as a third city
entirely. Known affected: Calls 38, 39, 50, 67, 134, 151, 156, 160, 185, 193.

**0% everywhere** — no attribution error can change that. Quote rate is not, because it can.

Fixing the store-label and call-direction tagging is the blocker on trustworthy per-store scoring
and remains the #2 item on the program plan.
