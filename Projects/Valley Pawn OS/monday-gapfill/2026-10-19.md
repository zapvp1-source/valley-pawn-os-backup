## What actually happened when the runner launched

`bin/monday_gapfill_runner.py` was launched as instructed (via `device_bash`, this session's
direct shell on the Mac — the `Control_your_Mac`/osascript tool genuinely does not exist in this
session's tool list, consistent with every prior session's finding back to 2026-10-15). It
exited almost immediately with `no monday-bravo-combined result.json found` (exit 1) — before
ever reaching its own `gapfill-2026-10-19.log` or `2026-10-19.md` writer, which is why this file
is written by hand instead of by the script.

**Root cause (confirmed by reading the script, not guessed):** `monday_gapfill_runner.py` (built
2026-09-05/06) hard-depends on `Bravo Data Extraction/results/monday-bravo-combined-*.result.json`
— the output of the Cowork scheduled task `monday-bravo-combined-run`. Per `CHANGELOG.md`
(entries around 2026-10-07/08: "DISABLED: monday-bravo-combined-run", "DISABLED:
monday-bravo-combined-compile", and Joshua's "turn these off, I give you full permission"), that
task and its combined-run/combined-compile pipeline were retired weeks ago. It has not produced a
`monday-bravo-combined-*.result.json` since 2026-09-06 (confirmed: no file matching that glob
exists anywhere under `Projects/`, only the much older per-report convention). The job it used to
feed was replaced by the native `com.valleypawn.monday-pull` agent (`bin/monday_pull.sh`, Sun
16:30 + Mon 05:30), which does its own health-gating, retries and writes the
`_monday_pull_status_<date>.txt` certificate directly — no Cowork session, no osascript, no
combined result.json involved. **`monday_gapfill_runner.py` is checking a data source that no
longer exists; the live safety net for this job is already the native `monday-pull` agent and its
certificate, not this script.**

This did not cost anything tonight because the native pull came back ALL CLEAN on its own. It
would matter on a night the native pull comes back with a named incomplete report — on that
night this gapfill runner would still find nothing and do nothing, because it is looking at the
wrong file. Flagging this now (Rule 15 — fix forward, not just report) rather than waiting for a
night it's actually needed and silently doing nothing.
